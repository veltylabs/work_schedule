# work-schedule — LLM Skill Summary

## Purpose
Read-only adapter over legacy `staff` and `workcalendar` tables, owned by an external system.
Exposes a single op (`get_work_schedule`) that returns a staff member's weekly schedule.

## Key Files
| File | Role |
|------|------|
| `model.go` | `StaffModel`/`WorkCalendarModel`/`GetWorkScheduleArgsModel`/`ScheduleEntryModel`/`StaffResponseModel` (`model.Definition` literals) |
| `model_orm.go` | Auto-generated by `ormc` — DO NOT EDIT |
| `module.go` | `Module`, `New(db)`, `GetWorkSchedule(staffId)` — the service |
| `ops.go` | `ModelName()`, `MountOps(reg router.OpRegistry)` — the transport binding |
| `tests/work_schedule_test.go` | All tests (package `tests`, `orm.New(mem.New())`) |

## Constraints
- **No DDL, ever.** Never call `ddl.CreateTable`/`ddl.Sync` (or the removed `orm.DB.CreateTable`)
  for `staff` or `workcalendar` — this module does not own their schema. See `AGENTS.md`'s domain
  notes; do not "fix" this by adding a migration call.
- **No `model.IDGenerator`, no `Deps`.** This module never constructs a row.
- **No `view.Presenter`.** A single detail lookup, not a list — see `docs/ARCHITECTURE.md` §3.4.
- `password_hash` has `Exclude: true` in `StaffModel` — it exists on the generated struct, never
  read or written by the ORM codec.
- `staff_id` arrives via `router.Context.Decode(&args)` — no validation beyond what `Decode` itself
  does; a missing/zero `staff_id` surfaces as `ErrStaffNotFound`, not a separate "invalid params".
- `start`/`end` are omitted from `ScheduleEntry` when `is_active = false` (`OmitEmpty: true`).

## Transport Registration

sched := workschedule.New(db)   // *orm.DB, no Deps
